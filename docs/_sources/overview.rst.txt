Overview
========

GeoAquaCrop Visualizer is a Dash application that renders an interactive
dashboard for post-processing and exploring gridded AquaCrop-OSPy simulation
results. The application code lives in the ``geoaquacrop_plotting`` package;
``geoaquacrop_plots.py`` is a thin entry point that imports it and calls
:func:`~geoaquacrop_plots.main`.

Features
--------

Simulation Outputs tab
~~~~~~~~~~~~~~~~~~~~~~
- Choropleth map of yield, water-balance, and water-productivity variables.
- Per-season and multi-year aggregated views (mean or sum), pre-computed at
  startup so switching variables is a dictionary lookup.
- Lasso / box selection of cells for spatial subsets, highlighted on the map
  and reusable as the spatial extent of an export.
- Daily time series for any clicked cell: water fluxes, soil water, and
  crop development.
- Interactive mean ± standard-deviation window tool on time series: click
  two points to define the window, a third to clear it.
- Pre-season shading marking the model spin-up period before the first
  planting.

Inputs tab
~~~~~~~~~~
- Choropleth map of maximum/minimum temperature, precipitation, and
  reference ET. Temperatures are shown as period means; precipitation and
  reference ET as period totals.
- Per-year or full-period aggregation.
- Daily climate time series with one planting-date overlay per simulation
  year, taken from the crop calendar for the currently selected crop.
- SPAM crop-area overlay for rainfed and irrigated extents, shown in place
  of the climate layer when a SPAM button is pressed.

Export
~~~~~~
- Export daily gridded output to NetCDF (``.nc``), GeoTIFF (``.tif``), or
  CSV.
- Flexible date range and spatial subset (whole area or lasso selection).

Package layout
--------------

.. list-table::
   :header-rows: 1
   :widths: 32 68

   * - Module
     - Responsibility
   * - ``config``
     - USER CONFIGURATION: workspace discovery, paths, canvas sizes, and the
       three variable catalogues.
   * - ``utils``
     - Stateless helpers — zoom, colour, date clamping, and the boundary
       simplification routines. Touches no dataset.
   * - ``data``
     - Loads every dataset once at import and derives the shared lookup
       tables.
   * - ``grid``
     - Builds the cell-polygon GeoJSON, the map centre, and the auto zoom.
   * - ``boundary``
     - Thins the region outline at startup and serves it from a route on the
       Dash server.
   * - ``aggregates``
     - Pre-computes every (crop, variable, aggregation) combination.
   * - ``queries``
     - Read-only accessors over the loaded datasets, several of them cached.
   * - ``export``
     - NetCDF / GeoTIFF / CSV gridded export.
   * - ``figures_maps``
     - Choropleth figure builders (output, climate, SPAM).
   * - ``figures_timeseries``
     - Time-series figure builders and the shared mean ± std band.
   * - ``styles``
     - Style constants, style factories, and small sidebar widgets.
   * - ``app_shell``
     - The ``dash.Dash`` object and the HTML index template.
   * - ``layout_sidebar``, ``layout_panels``, ``layout_export``, ``layout``
     - The left sidebar column, the right canvas column, the export modal,
       and the assembly of all three into ``app.layout``.
   * - ``callbacks_controls``, ``callbacks_selection``, ``callbacks_maps``,
       ``callbacks_timeseries``, ``callbacks_export``
     - Callback registration, grouped by concern.

Every module stays under 500 lines, and imports flow strictly one way. See
:doc:`architecture` for the full dependency order.

Requirements
------------

.. list-table::
   :header-rows: 1
   :widths: 34 66

   * - Package
     - Purpose
   * - Python 3.10+
     - Runtime
   * - pandas
     - Data manipulation
   * - numpy
     - Array operations, and the boundary simplification in ``utils``
   * - xarray
     - NetCDF climate, crop-calendar, and SPAM grids
   * - netCDF4
     - xarray engine for those ``.nc`` files
   * - scipy
     - Numerical support
   * - plotly
     - Interactive figures
   * - dash
     - Web application framework
   * - dash-bootstrap-components
     - Sidebar, accordions, and the export modal
   * - rasterio *(optional)*
     - GeoTIFF export

``pyproject.toml`` lists these without version constraints, so pip resolves
whatever is current. If you need a reproducible environment, capture one with
``pip freeze`` after a working install.

.. warning::

   Plotly 6 or newer is required. The maps use the MapLibre trace API
   (``go.Choroplethmap`` / ``go.Scattermap``); the older ``*mapbox`` traces
   were removed in Plotly 6.0. Because the dependency is unpinned, pip will
   not enforce this — an older Plotly resolved into the environment fails at
   import rather than at install time.

Quick start
-----------

.. code-block:: bash

   git clone https://github.com/sehohosseini/Geoaquacrop-visualizer2.git
   cd Geoaquacrop-visualizer2
   pip install -e ".[geotiff]"
   geoaquacrop-visualizer

Then open ``http://localhost:8050`` in your browser. On startup the app
prints the auto-computed zoom level and the region-boundary statistics
before Dash begins serving:

.. code-block:: text

   Auto zoom: 4.5
   Region boundary: 104 polygons, 207 rings, 12535 vertices, 0.28 MB served from /region-boundary.geojson
   Dash is running on http://127.0.0.1:8050/

See :doc:`installation` for the alternatives to the console script and
:doc:`configuration` for pointing the app at a different simulation run.

Input data structure
--------------------

The application expects the following preprocessed files in
``PROCESSED_DIR``:

.. list-table::
   :header-rows: 1
   :widths: 40 60

   * - File
     - Description
   * - ``MaxTemp<YYYY><YYYY>.nc``
     - Daily maximum temperature grid
   * - ``MinTemp<YYYY><YYYY>.nc``
     - Daily minimum temperature grid
   * - ``Precipitation<YYYY><YYYY>.nc``
     - Daily precipitation grid
   * - ``ReferenceET<YYYY><YYYY>.nc``
     - Daily reference ET grid
   * - ``cropcalendar.nc``
     - Planting DOY and growing season length per crop
   * - ``spam*_physical_area.nc``
     - SPAM crop physical area *(optional)*

The year suffix is derived from the simulation period rather than
configured: ``data`` reads the daily tables, builds the date index, keeps
every year with more than five days of data, and looks for
``<Variable><first_year><last_year>.nc`` — e.g. ``MaxTemp20082010.nc``. If
that exact filename is missing, it falls back to the first glob match for
``<Variable>*.nc``, so a differently named file in the same directory still
loads.

Simulation outputs are loaded from two pickle files:

- ``summary_results_*.pkl`` — a list of per-cell DataFrames of seasonal
  aggregated results. Rows carrying an ``error`` value are skipped when
  ``cell_meta`` is built, so failed cells never reach the map.
- ``daily_results_*.pkl`` — a list of per-cell dicts, each holding a
  ``water_flux`` and a ``crop_growth`` daily table.

The region outline is read from ``GEOJSON_PATH`` into
:data:`~geoaquacrop_plotting.data.region_geojson` at full resolution, and a
thinned copy is derived from it in memory at startup and served by URL. No
geometry is bundled with the package; see :ref:`boundary-simplification`.
