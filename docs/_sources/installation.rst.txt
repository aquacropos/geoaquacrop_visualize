Installation
============

Getting the source
------------------

.. code-block:: bash

   git clone https://github.com/sehohosseini/Geoaquacrop-visualizer2.git
   cd Geoaquacrop-visualizer2

``pyproject.toml`` declares the dependencies and makes the project
pip-installable. They carry no version constraints, so pip resolves whatever is
current; if you need a reproducible environment, capture one with
``pip freeze`` after a working install. A virtual environment is worth creating
first:

.. code-block:: bash

   python -m venv .venv
   source .venv/bin/activate        # Windows: .venv\Scripts\activate

Installing the package
----------------------

.. code-block:: bash

   pip install -e .

Use the editable (``-e``) form. ``config.py`` locates the data trees by
searching upward from its own file and from the working directory (see
:ref:`workspace-discovery`); an editable install leaves the package inside
the checkout, where that search resolves without help. A plain
``pip install .`` copies the package into ``site-packages`` — the search
still succeeds when the environment lives inside the workspace, but setting
``GEOAQUACROP_ROOT`` is the reliable way to pin it.

Extras
~~~~~~

.. list-table::
   :header-rows: 1
   :widths: 22 78

   * - Extra
     - Contents
   * - ``geotiff``
     - ``rasterio`` — required only for GeoTIFF export.
       :func:`~geoaquacrop_plotting.export.export_data` degrades gracefully
       without it.
   * - ``test``
     - ``pytest``
   * - ``docs``
     - ``Sphinx``, ``sphinx-rtd-theme``
   * - ``dev``
     - All three of the above.

.. code-block:: bash

   pip install -e ".[geotiff]"
   pip install -e ".[dev]"

Running the application
-----------------------

Installing the project registers a console script:

.. code-block:: bash

   geoaquacrop-visualizer

which is equivalent to running the entry point directly:

.. code-block:: bash

   python src/geoaquacrop_plots.py

Both call :func:`~geoaquacrop_plots.main`, which serves the app on the port
set by ``config.PORT`` with ``debug=False``.

Embedding in another server
---------------------------

``app`` is a plain ``dash.Dash`` instance, fully built by the time the import
returns, so the underlying Flask server can be handed to any WSGI host:

.. code-block:: python

   from geoaquacrop_plotting import app
   server = app.server          # WSGI entry point for gunicorn etc.

Note that ``app.server`` also carries the region-boundary route registered by
:mod:`geoaquacrop_plotting.boundary`, so the outline is served correctly under
any WSGI host without extra configuration.

Running the tests
-----------------

.. code-block:: bash

   pip install -e ".[test]"
   pytest

The suite runs **without the simulation data**. ``tests/conftest.py`` points
``GEOAQUACROP_ROOT`` at an empty stub directory and registers a stub parent
package, so the data-free modules (``config``, ``utils``, ``styles``,
``app_shell``) are imported and tested for real, while the data-loading
modules are covered by mirroring their logic against synthetic fixtures.

Beyond behaviour, the suite enforces the structural invariants described in
:doc:`architecture`: module line limits, an acyclic import graph, callbacks
that never import each other, and data loaded in exactly one place.

Building the documentation
--------------------------

The reStructuredText sources live in ``docs_src/``; ``docs/`` holds the built
HTML and is committed so it can be served directly (for example by GitHub
Pages — a ``.nojekyll`` marker is included for that).

.. code-block:: bash

   pip install -e ".[docs]"
   sphinx-build -b html docs_src docs

.. important::

   Unlike the test suite, the documentation build **does** import
   ``geoaquacrop_plotting``: the API pages are generated by ``autodoc`` from
   the real docstrings, which is what keeps them from drifting away from the
   code. The build therefore needs the simulation data present, or
   ``GEOAQUACROP_ROOT`` pointing at it. Without it the narrative pages still
   build and Sphinx reports an autodoc import error for each module,
   leaving the API pages empty.

Set ``SPHINX_NO_INTERSPHINX=1`` to skip the intersphinx inventory downloads
when building offline.
